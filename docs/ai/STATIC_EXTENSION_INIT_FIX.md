# Static Extension Initialization Fix

**Date**: 2025-12-28
**Issue**: Static extensions not loading in packaged `ruby.com` binaries
**Status**: ✅ Fixed

## Problem

After building and packaging `ruby.com`, attempting to load static extensions failed with:

```
dlopen() isn't supported; consider using cosmo_dlopen() - /zip/lib/ruby/3.4.0/extensions/x86_64-cosmo/monitor.so (LoadError)
```

Extensions like `monitor.so`, `socket.so`, `io/nonblock.so`, etc. were not being initialized even though:
- Extension `.a` archives were built correctly
- Extensions were linked into the binary
- The `Init_ext()` function was being called

## Root Causes

### 1. Missing EXTSTATIC Definition

**File**: `third_party/ruby-wip-3.4.7/ext/extinit.c`

The `extinit.c` file uses conditional compilation:

```c
void Init_ext(void) {
#if defined(EXTSTATIC) && EXTSTATIC
    init(Init_monitor, "monitor");
    init(Init_socket, "socket");
    // ... all other extensions
#endif
}
```

However, `EXTSTATIC` was **not defined** during compilation, causing the entire initialization block to be compiled out. The resulting `Init_ext()` function was empty (just `nop; ret` in assembly).

**Evidence**:
```bash
$ objdump -d o//third_party/ruby/ext/extinit.o
0000000000000010 <Init_ext>:
  10:	66 90                	xchg   %ax,%ax  # NOP
  12:	c3                   	ret              # Immediate return
```

### 2. Stub Path Mismatch

**File**: `third_party/ruby-wip-3.4.7/load.c`

Ruby's require system finds zero-byte stub files at paths like:
```
/zip/lib/ruby/3.4.0/extensions/x86_64-cosmo/monitor.so
```

But the static extension init table registers them with short names:
```
monitor.so
io/nonblock.so
```

The `run_static_ext_init()` function couldn't match the full stub path to the registered basename.

## Solution

### Fix 1: Define EXTSTATIC During Compilation

**File**: `third_party/ruby-wip-3.4.7/ruby.deps.mk` (lines 1090-1096)

Added target-specific CFLAGS to compile `extinit.o` with proper definitions:

```makefile
# extinit.c needs EXTSTATIC and SLIM_STATIC defined to match config.h
# This enables static extension initialization for static/slim_static builds,
# and disables it for dynamic builds (which use dmyext.c instead).
o/$(MODE)/third_party/ruby/ext/extinit.o: private		\
	CFLAGS +=						\
		-DEXTSTATIC=$(RUBY_EXTSTATIC)			\
		-DSLIM_STATIC=$(RUBY_SLIM_STATIC)
```

The values are read from `third_party/ruby/include/ruby/config.h`, which is generated by `cosmo_configure.sh` based on build mode:

- **slim_static**: `EXTSTATIC=1`, `SLIM_STATIC=1`
- **static**: `EXTSTATIC=1`, `SLIM_STATIC=0`
- **dynamic**: `EXTSTATIC=0`, `SLIM_STATIC=0`

### Fix 2: Stub Path Detection

**File**: `third_party/ruby-wip-3.4.7/load.c` (lines 1219-1237)

Enhanced `run_static_ext_init()` to detect stub paths and extract the basename:

```c
static bool
run_static_ext_init(rb_vm_t *vm, const char *feature)
{
    st_data_t key = (st_data_t)feature;
    st_data_t init_func;

    // Try direct lookup first
    if (vm->static_ext_inits && st_delete(vm->static_ext_inits, &key, &init_func)) {
        ((void (*)(void))init_func)();
        return true;
    }

    // If the feature looks like a stub path, extract basename
    // /zip/lib/ruby/3.4.0/extensions/x86_64-cosmo/monitor.so -> monitor.so
    const char *extensions_marker = "/extensions/";
    const char *stub_path = strstr(feature, extensions_marker);
    if (stub_path) {
        const char *after_extensions = stub_path + strlen(extensions_marker);
        const char *basename = strchr(after_extensions, '/');
        if (basename) {
            basename++; // Skip the '/'
            key = (st_data_t)basename;
            if (vm->static_ext_inits && st_delete(vm->static_ext_inits, &key, &init_func)) {
                ((void (*)(void))init_func)();
                return true;
            }
        }
    }

    return false;
}
```

This handles both simple extensions (`monitor.so`) and nested ones (`io/nonblock.so`).

## How It Works

1. **At build time**: `extinit.c` is compiled with `-DEXTSTATIC=1`, enabling all `init()` calls
2. **At link time**: Extensions are linked with `--whole-archive`, pulling in all `Init_*` functions
3. **At startup**: `Init_ext()` calls `ruby_init_ext()` for each extension with weak symbol checks
4. **At require time**: When requiring a stub `.so` file, the basename is extracted and looked up in the static init table

## Cross-Mode Compatibility

The fix works correctly for all three build modes because it uses values from `config.h`:

| Mode | EXTSTATIC | SLIM_STATIC | Behavior |
|------|-----------|-------------|----------|
| **slim_static** | 1 | 1 | Static extensions + zero-byte stubs |
| **static** | 1 | 0 | Static extensions only |
| **dynamic** | 0 | 0 | Uses `dmyext.c` (stub registration) |

## Technical Notes

- **Weak symbols**: Extensions use `__attribute__((weak))` so they're only initialized if linked
- **--whole-archive**: Necessary to extract all `.o` files from `.a` archives (weak symbols don't create undefined references)
- **Zero-byte stubs**: Kept for discoverability in `/zip/lib/ruby/3.4.0/extensions/` (architect preference)
- **Stub path format**: `/zip/lib/ruby/3.4.0/extensions/<arch>/<extension>.so`
- **Registration format**: `<extension>.so` or `<subdir>/<extension>.so` (basename after arch directory)

## Lessons Learned

1. **Conditional compilation**: Always verify preprocessor defines are actually set during compilation
2. **Disassembly debugging**: `objdump -d` quickly reveals if code blocks are compiled out
3. **Path normalization**: When using filesystem markers, ensure lookup logic handles both full paths and basenames
4. **Cross-mode testing**: Test all build configurations (static, slim_static, dynamic) to ensure fixes work universally
